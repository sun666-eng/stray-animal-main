# 用户端体验契约

## 设计方向

用户端使用“暖白编辑式救助档案”：暖白纸张、墨黑标题、朱红主行动、绿色完成态和琥珀处理态。视觉服务于真实救助流程，不使用无业务含义的图表或演示数字。

## 五类页面

- `discovery`：首页、动物列表、动物详情、收藏。先理解动物，再采取行动。
- `application`：领养、救助、义工申请。减少认知负担，允许暂存并明确隐私边界。
- `journey`：我的领养、材料、回访、救助、义工和通知。优先展示当前状态与下一步。
- `content`：救助动态、公告详情、透明公示。说明来源、时间和统计口径。
- `assistant`：照顾知识助手。区分平台数据、模型建议和医疗边界。

## 不可破坏的业务原则

1. 页面数据继续来自现有接口，不把原型演示数字写入产品。
2. 动物图片按“真实文件标识 → 编辑式缺图占位 → 加载失败占位”回退。
3. 失败状态不得保留旧数据并伪装成功；写请求失败必须保留用户输入。
4. 领养、救助、义工状态只使用系统既有状态机和 `status-text.js`。
5. 桌面、平板、手机保持同一信息优先级；320px 不产生横向滚动。

## 共享组件

- `front-site-header` / `front-site-footer`：公共导航和账户入口。
- `front-member-sidebar`：登录用户的行动与工具导航。
- 页面标题、统计摘要、状态徽标、错误/空状态和确认对话框使用 `product-ui.css` 统一规则。

## 静态资源发布

`tools/front-asset-version.txt` 是用户端 `product-ui.css`、`user-workspace.js` 和 `front-shell.js` 的版本单一事实源。发布前必须运行：

```text
node tools/front-asset-version.cjs --check
```
