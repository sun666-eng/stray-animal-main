# 管理员工作区设计契约

管理员端采用同一套编辑式 Command Desk 视觉语言，但不强制所有业务页面使用相同 DOM。

## 共同约束

- 主内容使用 `admin-main`，宽度、页边距和移动端收口由共享 CSS 管理。
- 每页只有一个带 `id` 的 `h1`，主视觉区通过 `aria-labelledby` 引用它。
- 共享暖白纸张、墨黑文字、朱红强调、统一状态色和按钮层级。
- 列表、工作流、仪表盘和对话工作区可以使用不同的信息架构。
- 所有管理员页面共享同一静态资源发布版本，禁止按页面维护不同 cache-bust。

## 工作区类型

- `command`：档案、用户、角色、权限、凭证、回访等标准治理页。
- `workflow`：领养审核和救助处置，保留状态机与领域操作布局。
- `hub`：管理首页和运营中心，保留跨业务导航与汇总布局。
- `profile`：个人资料，强调身份、安全边界和显式保存。
- `agent`：AI 管理助手，强调只读证据、人工决定和受控自动化。

`data-workspace-variant` 是契约标记，不应被当成要求页面外观完全相同的依据。

## Agent 信息语义

- Hero 指标是当前系统概览；显示本次概览成功更新时间。
- 对话回答只呈现该轮读取证据，不在回答气泡下重复一套“实时”指标。
- 待办类数值大于 0 使用提醒色；可用动物档案大于 0 使用正常色、等于 0 使用提醒色。
- 会话搜索只筛选当前已加载的最多 50 条会话，界面必须明确说明范围。
- 受控模式的保存与运行是两个动作；每次运行前仍需完成两项确认和确认短语，未完成时运行按钮保持禁用。

## 响应式原则

- 宽桌面可使用三栏 Agent 工作区。
- 1366px 及更窄桌面将上下文区下沉，避免历史、对话、控制三栏同时挤压。
- 手机端使用单列内容和会话抽屉；不得依赖整页横向滚动。

## 门禁

```powershell
node tools/admin-asset-version.cjs --check
node tools/admin-workspace-contract.cjs
```

两项检查都必须严格通过，才允许进入浏览器视觉和交互回归。
